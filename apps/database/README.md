# Документация базы данных проекта

Добро пожаловать в техническую документацию структуры базы данных проекта. Данный репозиторий содержит описание схемы данных, связей между таблицами, ограничений целостности и бизнес-логики работы с ключевыми сущностями.

## Навигация по документации

Для детального изучения структуры таблиц перейдите в соответствующие разделы:

1. 📅 **[Документация по посещаемости (Attendance) и расписанию](./docs/attendance.md)**
   - Таблицы: `attendance`, `attendance_preset`
   - Смежные сущности: `learning_topics`, `users` (тренеры), `quality` (оценка качества)
   - Ограничения целостности (CHECK constraints) для типов занятий (индивидуальные, групповые, пробные)
   - Логика регулярных расписаний на основе правил повторения (`rrule`)

2. 🎓 **[Документация по ученикам (Students) и группам](./docs/students.md)**
   - Таблицы: `students`, `students_groups`, `reports` (отчеты успеваемости)
   - Связи между учениками, группами и отчетами
   - Логика хранения отчетов и распределения по учебным группам

---

## Общие архитектурные принципы

- **Идентификаторы**: В качестве первичных ключей во всех таблицах используются UUID версии 4 (`VARCHAR(36)`).
- **Связи**: Целостность данных поддерживается на уровне СУБД MySQL с помощью внешних ключей (`FOREIGN KEY`) с каскадными ограничениями там, где это необходимо.
- **Бизнес-правила**: Сложные правила валидации (например, недопустимость одновременного указания ученика и группы для индивидуального занятия) вынесены на уровень ограничений `CHECK` базы данных для предотвращения логических ошибок.
