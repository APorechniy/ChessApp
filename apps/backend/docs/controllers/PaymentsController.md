# PaymentsController (Платежи ЮKassa)

Контроллер отвечает за интеграцию с платежным шлюзом ЮKassa, создание счетов на оплату, проверку статуса транзакций и обработку уведомлений от платежной системы.

## Эндпоинты

### 1. Получение статуса платежа
* **URL**: `/payments/status`
* **Метод**: `GET`
* **Авторизация**: Не требуется
* **Параметры запроса (Query)**:
  * `paymentId` (string, обязательно) — уникальный идентификатор платежа в системе ЮKassa.
* **Логика работы**:
  1. Извлекает `paymentId` из параметров запроса. Если он отсутствует, выбрасывает ошибку "Payment ID did not provided".
  2. Вызывает метод `paymentsService.getPaymentStatusById(paymentId)` для получения актуального статуса из платежного шлюза или локальной БД.
  3. Возвращает статус платежа.
* **Успешный ответ (200 OK)**:
  ```json
  {
    "status": "succeeded"
  }
  ```

### 2. Создание платежа
* **URL**: `/payments/`
* **Метод**: `POST`
* **Авторизация**: Требуется (`authCheck` middleware)
* **Тело запроса (JSON)**:
  ```json
  {
    "cost": 1500
  }
  ```
* **Логика работы**:
  1. Извлекает JWT-токен из cookie `jwt-token`. Если токен отсутствует или не содержит ID пользователя, возвращает ошибку доступа "Access denied".
  2. Проверяет корректность переданной суммы `cost` (должна быть больше 0). При некорректной сумме выбрасывает ошибку "Incorrect cost".
  3. Вызывает `paymentsService.createPayment(cost, userId)` для инициации платежа в ЮKassa.
  4. Получает `paymentId` и `widgetId` (для отображения платежного виджета на фронтенде).
  5. Возвращает данные для инициализации виджета оплаты.
* **Успешный ответ (200 OK)**:
  ```json
  {
    "widgetId": "num_...",
    "paymentId": "pay_..."
  }
  ```

### 3. Обработка уведомлений от ЮKassa (Webhook)
* **URL**: `/payments/notification`
* **Метод**: `POST`
* **Авторизация**: Не требуется (вызывается серверами ЮKassa)
* **Тело запроса (JSON)**: Соответствует структуре уведомлений ЮKassa (`UkassaNotificationBody`).
* **Логика работы**:
  1. Принимает уведомление о смене статуса платежа.
  2. Логирует в консоль ID платежа и событие.
  3. Парсит событие (например, `payment.succeeded` -> статус `succeeded`).
  4. Асинхронно вызывает `paymentsService.updatePaymentStatus` для обновления статуса платежа в БД, начисления средств на баланс пользователя и фиксации транзакции.
  5. Возвращает пустой ответ со статусом `200 OK` для подтверждения успешного приема вебхука.
* **Успешный ответ (200 OK)**: Пустое тело.
